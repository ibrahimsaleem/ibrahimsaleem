## About Me

I am an **AI Security & Governance Engineer** focused on securing enterprise-scale **LLM, GenAI, MCP, and agentic AI systems** across the full AI lifecycle: design, data handling, model integration, tool use, deployment, monitoring, and runtime governance.

My work sits at the intersection of **AI security engineering, adversarial testing, secure AI SDLC, AI governance, and autonomous-agent risk management**. I focus on practical security controls for real enterprise risks such as:

- Prompt injection and jailbreak attacks
- Tool poisoning and unsafe MCP server behavior
- Sensitive data leakage in LLM and RAG systems
- Excessive agency and unbounded autonomous actions
- Weak AI workflow authorization
- Insecure model/tool orchestration
- Poor observability and missing runtime controls
- AI product risk and permit-to-operate governance gaps

I am especially interested in building secure AI systems that are not only innovative, but also **auditable, controllable, monitored, and enterprise-ready**.

## Security Philosophy

AI systems should not be treated as normal software with a chatbot attached. LLMs and agents introduce new trust boundaries, new abuse paths, and new failure modes.

My approach:

1. **Assume prompts are hostile.**
2. **Assume retrieved context may be poisoned.**
3. **Assume tools can be misused.**
4. **Assume agents need identity, least privilege, logging, and runtime control.**
5. **Treat AI security as an operational system, not a one-time review.**
